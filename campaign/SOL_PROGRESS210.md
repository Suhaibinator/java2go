# Sol checkpoint 210: owned source-input snapshots

Parsed files can now retain an immutable snapshot of their input bytes and offset metadata. The API validates owner and root identity, current bytes, UTF-8 and offset bounds, returns defensive copies, and prevents repeated attachment or accidental reuse through a copied file object. Parser ingress attaches the snapshot through the existing file lifetime. Validation compares the complete input; redundant private SHA copies are not retained.

This is input evidence only. It does not prove AST contents came from those bytes, graph membership, a provider, or a semantic result. No compiler consumer gains admission from this API in this checkpoint. Later compiler features must separately establish actual syntax, declaration and graph ownership.

The exact final source passed all 87 qualification stages: 1,168 parent checks across 48 native jobs, complete parser and symbol suites in normal and race modes, existing lookup/allocation/native-call budgets, the exact 892-name F1 registry, six default/F1 build/test-compilation/lint profiles, and four byte-identical generated-Go comparisons against the prior public source. The two integration stages retained exactly eight existing Broken< warning callbacks each; their raw timestamped stderr is preserved and is not claimed byte-identical. All other native stderr was empty. An auditor's overly broad empty-stderr assumption was corrected to recognize only those existing warnings; no source, controller, payload or assertion was changed or rerun.

Six separately authorized cost build/metadata stages and four quiet measurement jobs also passed. All 238 rows from the baseline/candidate/candidate/baseline order were retained, including both samples and small inputs. Complete large-file Validate measured 8.52–9.37 microseconds with two allocations, 200–216 bytes and four native calls per invocation for the measured 105–122 KB inputs. Construction retained three allocations and about two input-buffer copies. These are current API costs, not a comparison with the earlier hashed implementation, an absent baseline API, or Java application performance; full input validation remains linear. The diagnostic harness stays outside tracked source.

Coordinator and independent reviews cover source, inputs, tools, binaries, exact commands, environments, native modes, raw streams and lifecycle records. All owned processes and groups were absent after each gate; the quiet lease was released before analysis. Existing historical failures remain preserved. Full hosted CI, public collector integration, Supplier28, Gson112 and Netty1220 application parity remain open. Separately qualified receiver and generic-factory test migrations require a coherent rebase before their publication.
