# Sol checkpoint 207: assignability FIFO and precise monitor observation

Runtime Java type assignability now retains and reuses its FIFO storage while walking registered supertypes. A small local buffer and amortized prefix compaction avoid discarding reusable capacity. Traversal order, nominal metadata and assignability results are unchanged. The fixed allocation regression exercises native ArrayList and an independently registered nominal subclass against unrelated Throwable: all twelve measured samples use three allocations per call, below the unchanged ceiling of six. Matched pre-fix samples used seven allocations normally and eight or nine under the race detector. This is an allocation result for the runtime operation, not a Java application throughput claim.

Integration exposed a pre-existing monitor test that compared the total registry size while asynchronous cleanup could remove unrelated entries. The test now watches each retained object's identity and weak epoch, including absent entries and empty weak tombstones. Controls demonstrate both the old count's false positive and its ability to miss a registration canceled by unrelated cleanup. The original zero-allocation and ownership checks remain; production monitor behavior is unchanged.

The final source passed sixteen fresh stages: all 888 runtime tests in normal mode and under the race detector, two monitor parents repeated twenty times in each mode, and all six default/F1 build, test-compilation and lint profiles. That is 1,856 parent passes. The coordinator and an independent Sol reviewer checked source and tool hashes, raw receipts, outputs, allocation samples and process cleanup. Four boxed compiler parents in each mode retain separate evidence from the immediately preceding source; those are not claimed as fresh final-source runs.

The earlier runtime integration failed the old monitor count assertion; the subsequent monitor repair failed lint on a redundant Boolean negation. Both failures and their raw evidence remain preserved. The final source changes only that test expression from the preceding qualification. No oracle, Java fixture, production repair or allocation ceiling was weakened.

Hosted checkpoint-206 CI still has 23 compiler failures, down from 24 after the boxing repair, plus the separate Gson Java-time failure. These are observations from the PR merge checkout. This checkpoint does not claim green hosted CI, full Netty application parity or universal Java support. Supplier28, Gson112 and Netty1220 remain open acceptance gates.
