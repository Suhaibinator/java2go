# Sol checkpoint 208: source functional-interface identity through casts

Generated adapters for source functional interfaces now always expose their declaration-owned Java type identity. Previously the compiler emitted this metadata only when array or reflection demand was detected, so a valid adapter could fail an Object cast. The constant metadata method now uses an unnamed receiver, avoiding collisions with generic binder names. Source Java methods named JavaDynamicTypeID receive the existing collision-safe method-family selector consistently across interfaces, inheritance and implementing classes; Object clone reservation remains class-only.

The repair preserves source interface binary names, including source Function and Supplier homonyms. It does not change runtime casts, provider admission or native anonymous functional-interface implementations. Tests prove that eligible source adapter declarations exist before checking metadata, that direct/default/inherited Java method collisions retain their behavior, and that ineligible declarations do not gain adapters.

The final source passed all 36 fresh stages: seven focused parent checks and twelve subtests, two strict-transpiled programs, four complete JVM/Go trace comparisons in normal and race modes, all generated packages built with the race detector, and six default/F1 build, test-compilation and lint profiles. CLI, compiler-test, runtime-test and generated binaries were freshly built against this source. The opaque/unknown-provider runtime shield passed under the race detector. Both lints reported zero issues. Two earlier qualified JDK21 observations and eleven class artifacts were retained with exact source, tool, argument, environment and raw-output bindings; this checkpoint claims no fresh JVM observations. Nested plain Go subprocesses receive no race credit.

The coordinator and independent Sol reviewer checked source, input, binary and tool hashes; exact commands and environments; raw traces and test names; and lifecycle evidence. All 73 owned PIDs and 36 groups were absent after qualification. Earlier adapter-count controls that guessed an uppercase generated receiver name remain preserved and uncredited; corrected controls identify the actual resolved declaration before asserting metadata.

This checkpoint does not claim a fresh full runtime execution, green hosted CI, native anonymous Function/Supplier compatibility or full Netty application parity. The last hosted checkpoint-206 result still has 23 compiler failures plus the separate Gson Java-time failure. Supplier28, Gson112 and Netty1220 remain open acceptance gates.
