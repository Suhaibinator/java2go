# Sol checkpoint 168: source Reader clone, generic signatures and virtual dispatch

A source Reader subclass could not clone its native state while retaining Java identity, protected lock state and most-derived callbacks. Its recursive generic aliases then exposed a Go compiler alias deadlock, generic receiver read calls missed the inherited native contract, and calls through a superclass view bypassed descendant read overrides. The cumulative repair closes these separate, reproduced prerequisites without replacing application behavior.

Source clone generation now requires an actual canonical native-Reader ancestry certificate and independent original declaration-root proof. It copies the Reader base into fresh field storage, preserves the existing Java lock reference and shallow user fields, allocates fresh object identity/monitor state and rebuilds dispatch against the clone. Canonical generic dispatch signatures use definitionally equal physical types only at proved signature positions, preserving public aliases, storage and value bodies. Reader read lowering retains the actual generic source declaration rather than looking up its rendered generic spelling.

At runtime, read invocation facades resolve registered source Readers to the same allocation's most-derived view before optional override dispatch. Actual nominal registration, a nonnull compatible view and Java reference identity are required; opaque/native protocols retain their existing path. Overrides receive the original Execution and arguments before inherited validation, so a descendant can observe null arrays and ordering as Java permits. Explicit super/default behavior remains separate. This adds three single-line facade hooks and a private helper; no registry or object-layout replacement is used.
