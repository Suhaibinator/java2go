# Sol checkpoint 182: Math extrema declarations, widths and edge cases

The full original Netty input stopped in PoolArena.java472 at imported Math.max(long,int), because import resolution had no modeled overload declarations. Math.min and max now register all four real JDK primitive overloads through the existing resolver. Canonical owner, source shadowing, ambiguity and strict-mode checks stay in place.

Independent application calibration then found that literal-only calls inferred Go int when Java required int32. The existing type-argument mechanism now instantiates min/max helpers at the promoted width derived from known Java primitive arguments. Consumer expected types and Go expression shapes do not donate that width; existing boxed and unknown paths retain their lowering. Both legacy callbacks use the same mechanism.

The original 60-row JDK calibration next exposed NaN-left and signed-zero errors in the runtime comparisons. MathMax/MathMin now preserve the first NaN, select Java signed zero and compare integers at their original width. A floating sign check runs only when both operands are zero, preserving long precision beyond2^53. This does not canonicalize arbitrary NaN payloads or claim a payload contract.
